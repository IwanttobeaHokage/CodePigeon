<h1 align="center">CodePigeon 🕊️</h1>

<p align="center">프로그래머스에서 문제를 푸는 <b>과정 전체</b>를 GitHub에 기록하는 크롬 확장</p>

맞은 코드만 남기는 기존 업로드 도구와 달리, **틀린 시도까지 순서대로** 남겨서 "이 문제를 내가 어떻게 풀어갔는지"를 나중에 다시 볼 수 있게 합니다.

## 기능

- **실패 기록**: 코드 실행이나 제출에서 틀리면 그때의 코드와 결과가 자동으로 기록됩니다.
- **정답 메모**: 제출에 성공하면 메모 창이 뜹니다. 코드에 `#` 주석을 달거나, 핵심 아이디어·주의할 점을 적어서 함께 올릴 수 있습니다.
- **참고 풀이 담기**: "다른 사람의 풀이" 페이지의 코드 블록마다 `💡 내 기록에 담기` 버튼이 붙어서, 좋은 풀이를 메모와 함께 같은 문제 파일에 저장합니다.
- **문제당 파일 하나**: `programmers/lv{0-5}/{문제번호}-{제목}.md`에 시도가 차례로 쌓입니다.
- 성공한 "코드 실행"은 어차피 제출 때 같은 코드가 올라가므로 기록하지 않습니다.

## 기록 예시

````markdown
# [Lv.0] [PCCE 기출문제] 2번 / 각도 합치기

## #1 · 실행 · ❌ 실패 · 2026. 11. 8. 오후 3:10:57
```python
def solution(a, b): return a + b
```
<details><summary>결과 보기</summary> … 1개 중 0개 성공 … </details>

## #2 · 제출 · ✅ 성공 · 2026. 11. 8. 오후 3:12:30
```python
def solution(a, b): return (a + b) % 360
```
> 📝 **메모**
> 360 넘는 경우를 생각 못 해서 처음에 틀림 → % 360

## 💡 참고 풀이 · 2026. 11. 8. 오후 3:20:02
````

## 설치

1. 이 저장소를 내려받습니다(`Code → Download ZIP` 후 압축 해제, 또는 `git clone`).
2. `chrome://extensions`에서 **개발자 모드**를 켜고, **압축해제된 확장 프로그램을 로드합니다**로 이 폴더를 선택합니다.
3. GitHub에서 [Fine-grained 토큰](https://github.com/settings/personal-access-tokens/new)을 만듭니다.
   - Repository access: 기록할 저장소 하나만
   - Permissions → Contents: **Read and write**
4. 확장 아이콘을 누르면 설정 페이지가 열립니다. 토큰, 저장소(`아이디/저장소명`), 브랜치를 입력하고 저장합니다.
5. 프로그래머스에서 문제를 풀면 오른쪽 아래 알림으로 기록 결과가 표시됩니다.

> 토큰은 브라우저의 `chrome.storage`에만 저장되고, GitHub API 외에는 어디로도 전송되지 않습니다.

## 구조

| 파일 | 역할 |
|---|---|
| `content.js` | 실행/제출 버튼 감지, 결과창 대기, 메모 창, 풀이 페이지 버튼 |
| `background.js` | GitHub Contents API로 파일을 읽고 이어 붙여 커밋 (업로드는 큐로 하나씩) |
| `format.js` | 성공 판정과 마크다운 형식 (content/background/테스트가 공유) |
| `options.*` | 토큰·저장소 설정 |
| `check.js` | `node check.js`로 판정/형식 셀프 테스트 |

## 만들면서 해결한 문제

- **메모 칸이 클릭되지 않음**: 프로그래머스의 채점 결과 팝업(Bootstrap 모달)이 jQuery의 document 캡처 단계에서 포커스를 되찾아갔습니다. Shadow DOM 모달에 대해 `window` 캡처 단계에서 `stopImmediatePropagation`으로 먼저 차단해서 해결했습니다.
- **연속 업로드 시 409 충돌**: 커밋 직후 GitHub가 이전 `sha`를 돌려주는 경우가 있었습니다. `cache: 'no-store'`로 다시 읽고, 409/422가 나면 재시도하도록 처리했습니다.
- **"1개 중 0개 성공"을 성공으로 판정**: 단어 검사 대신 `N개 중 M개`, `합계: X / Y`의 숫자를 비교하도록 바꿨습니다.
- **풀이 페이지에서 레벨을 못 읽어 다른 폴더에 저장됨**: 문제 페이지에서 본 메타 정보를 저장해 두고, 업로드 전에 같은 문제 번호의 파일을 트리에서 먼저 찾도록 했습니다.
